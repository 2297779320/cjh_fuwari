AI 分类又添一篇——这次是精读布鲁斯AI的《给 Hermes 装上一群同事：Oh My Hermes 把 agent 编排做成了基础设施》。

先说清它是什么：**Oh My Hermes（OMH）不是新模型，也不是 Hermes 的替代品**，而是加在 Hermes Agent 上的一层运行层。你照旧跟 Hermes 说话，它把每件事拆成几条 lane，每条 lane 配一个「带技能、带模型、带推理档位」的同事并行去干。MIT 许可，5.4k 星，当前 v4.0.7。原文作者点出了三条最实在的设计：**18 类工作各有模型链、153 个专家技能由路由器自己挑、没验证过不算做完**。

## 一、产品哲学：入口不变，内部换架构

OMH 对 Hermes 有三条承诺：

- **不替换、不打补丁**：继续用原来的 Hermes，OMH 只在上面加「哪条线该用哪个模型、带哪些技能」的编排；Hermes 自己的记忆它从不读取，也不改写
- **每条 lane 是一个同事**：lane 不是线程，是「有技能、有模型、有档位的执行单元」。一句话定目标，它拆成若干 lane 并行跑
- **没验证过，不算做完**：每个状态都写明自己停在哪一步，只有真跑过测试/评审/CI 的那一档才算 verified

官网那句总结最准：**你继续跟 Hermes 说话，OMH 给每条 lane 挑一个技能和一个模型，然后并行把活干完。** 产品哲学一句话：入口不变，内部换架构——不用学新语法，也不用把工作流搬进新工具，复杂度藏在下面。

顺带一个细节：项目把 AI 角色 Kami、Friren 真的写进了 README 的 contributor 列表，Kami 还承担了一部分实际开发。**把 AI 同事写进贡献者名单，比写在宣传语里更有说服力。**

## 二、核心命令 /dag-ulw：目标变图，图变 lane 树

敲下 `/dag-ulw`，你的目标变成一张 DAG：拆成小节点，就绪的节点并行跑，每条用自己的模型和档位。两个关键设计：

1. **并行节点不共享写入范围**——并行最容易出的问题不是慢，是两个节点同时改同一个文件，最后一个把另一个覆盖掉。把写范围切开是并行的前提，不是优化项
2. **跑完有专门的验收节点**，检查目标达成没有；失败的节点先被修复，然后才出报告——不是把错误原样甩给你

跑起来之后是一棵 **lane 树**：每条 lane 显示模型、推理档位、消耗的 token、当前状态。这是「并行」第一次变得可观察——不是黑箱里同时烧钱，而是每条线摊开给你看。

## 三、18 类工作，各自一条模型链

最反直觉的设计：**模型不是全局选一个，而是按工作分类选**。例如：

| 分类 | 模型链（示例） |
| --- | --- |
| ultrabrain（最深推理） | Fable 5.2 → Opus 5.5 → Kimi |
| quick（短任务） | GLM 5.3 Flash → GPT-6 Luna → Haiku |
| review（换模型挑刺） | GPT-6.1 Sol → Opus 5.5 |
| swarm（多工人分片） | DeepSeek Flash → GLM Flash |

关键规则是 **No silent downgrade**：服务商拒绝某个模型时，链往下顺延，而不是悄悄换成便宜货。链可以在 `~/.omh/routing/model-chains.json` 里改，改完 `omh model-chains show` 看实际生效配置；命令行还有选择器（方向键选分类、左右换主模型、加减号调档位）。

为什么按分类路由比手动选省事？真实工作里同一件事在不同阶段需要的模型不一样——写代码要强推理、写文案要语感、做视觉要审美、长任务要撑上下文。手动选等于每一步都想一次；按分类路由把判断提前做成模板，只在结果不对时才改链。

## 四、四级完成状态：整个项目最值钱的设计

**Plan · 未运行** → **Code · 运行中** → **Code · 执行者说完成** → **Test · 已验证**。

大多数 agent 报完成，你只能信它。这里把「谁说的」和「验过没有」分开了。为什么这条比功能表重要？因为 agent 最常见的失败不是不会做，是**做了但没做成，还说做成了**。把它变成状态机之后，你在任何时刻都知道进度停在哪一档，也大概知道该不该信。**自己搭流水线的话，这条设计可以直接抄。**

## 五、十条 ulw 工作流与 153 个技能

`ulw-*` 是旗舰工作流族，十条覆盖长周期任务的不同阶段：术语对齐 → 深访澄清（一次只问一个问题）→ 有据研究（实时网页证据）→ 评审过的计划 → 并行交付 → 图执行 → 外派给 Claude Code / Codex（真的起会话、可中途干预）→ 目标循环 → 对抗式 QA → 可测优化。每条都能用中文触发：「deep-interview 帮我理清需求」「ultraqa 做发布前验收」。

随包发 **153 个 `omh-*` 专家技能**（前端、后端、Rust、安全评审、验证闸门……），你一个都不用点：路由器根据当前这一步在干什么，把该用的技能作为工具调用装进运行里。官网原话：**153 skills. You never call them.** 技能是资产，不是配置负担。

## 六、三条容易忽略的能力

- **LSP 进环路**：定义、引用、重命名来自语言服务器而不是文本搜索，别名、re-export、被遮蔽的同名变量都按语义改。默认关闭，插件设置里开 `lsp_tools`
- **可审计的长期记忆**：没有东西被偷偷记住——每条候选记忆要么保留、要么拒绝、要么延后，都带一句书面理由；下次会话拿到的是按任务排序、按 token 预算裁剪的召回包
- **OMH Native**：敲 `omh` 打开自己的 TUI（跑在 Hermes 的 gateway 上），`/dag-ulw` 先打印框线图再给实时 lane 树，`!` 跑一行 shell，Esc Esc 回退

## 七、安装：装、配、验三件事分开

```bash
curl -fsSL https://omher.app/install | sh
omh setup     # 模型与分类的引导配置
omh doctor    # 出问题时的排查入口
```

macOS / Linux / Windows 都有脚本，Homebrew、bun、npm 也能装（npm/bun 路线要求 Node 18+，安装脚本自己找 Python 3.11+）。装完 `omh update` 会顺着安装方式自我升级，顺带刷新技能与插件。

一个值得抄的供应链细节：它给「粘给你的 AI agent」的安装指令里，要求**先把 main 解析成完整 commit SHA，再按那个 SHA 执行**——防「仓库中途被改」。

建议的上手顺序：先 `omh doctor` 体检，再用一条最普通的任务看它怎么拆 lane、怎么标状态；确认「它报完成的时候是真完成」，再把长活交给它。

## 八、五盆冷水

1. **它是 Hermes 上的一层**——没有 Hermes 就没有它，Hermes 本身仍要装、配、给凭据
2. **模型要花钱**——18 条链串的是各家前沿模型，跑长活就是真金白银；路由配置不等于额度
3. **并行不等于免费**——lane 越多同时烧得越多，swarm 档就是为此准备的，用哪档要自己判断
4. **证据要靠测试撑着**——verified 要求真跑过测试/评审/CI；项目里没有测试，它也只能停在「执行者说完成」
5. **桌面端还在迭代**——v4.0.7，issue 常开，桌面 App 和 TUI 两套入口能力不完全对齐

## 写在最后

原文结尾那句话很到位：在所有人都在比「谁的模型更强」的时候，这个项目赌的是另一件事——**编排和证据，比模型本身更稀缺**。一个目标进来，拆成图，交给一群各有所长的同事，跑完还得有人签字；这套流程不是 AI 发明的，是工程管理本来的样子，OMH 只是把它写成了代码然后开源。

对照站内 DSH 系列：DSH 的核心是「一切皆插件」，OMH 的核心是「一切皆编排 + 证据」——[《DSH 进阶精读》](/posts/ai/dsh-dev-guide/)讲的是单 agent 框架的组装，OMH 讲的是多 agent 任务图的调度，正好是 1 和 N 的关系；再往前对照[《Claude Code 精读》](/posts/ai/claude-code-playbook/)，三篇连起来能看清 agent 产品化的三条路线：harness 深化、插件生态、多 agent 编排。
