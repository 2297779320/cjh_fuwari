V4L2（Video for Linux 2）是 Linux 中关于视频设备的内核驱动框架。在 Linux 中，视频设备是设备文件，可以像访问普通文件一样对其进行读写。本文主要讲解用户态的 V4L2 视频采集流程，包括创建、运行、销毁等。

> 内核驱动层面的对象模型（`video_device`、`v4l2_subdev`、`vb2_queue` 等）见另一篇[《V4L2 驱动对象模型精读》](/cjh_fuwari/posts/linux/v4l2-driver-model/)，两篇互补。

## 常用结构体与命令

头文件 `<linux/videodev2.h>` 中的常用结构体：

```c
struct v4l2_capability      /* 视频设备的功能，对应命令 VIDIOC_QUERYCAP */
struct v4l2_input           /* 视频输入信息，对应命令 VIDIOC_ENUMINPUT */
struct v4l2_standard        /* 视频制式，如 PAL、NTSC，对应命令 VIDIOC_ENUMSTD */
struct v4l2_format          /* 帧格式，对应命令 VIDIOC_G_FMT、VIDIOC_S_FMT 等 */
struct v4l2_requestbuffers  /* 申请帧缓冲，对应命令 VIDIOC_REQBUFS */
struct v4l2_buffer          /* 驱动中的一帧图像缓存，对应命令 VIDIOC_QUERYBUF */
struct v4l2_crop            /* 视频信号矩形边框 */
v4l2_std_id                 /* 视频制式 */
```

ioctl 原型：`int ioctl(int fd, unsigned long request, ...)`，其中 `fd` 是 `open()` 打开视频设备后返回的文件描述符，`request` 是具体的命令标志符。

V4L2 开发中常用的命令：

| 命令 | 作用 |
| --- | --- |
| `VIDIOC_QUERYCAP` | 查询驱动功能 |
| `VIDIOC_QUERYSTD` | 检查设备支持的视频制式（PAL/NTSC） |
| `VIDIOC_ENUM_FMT` | 枚举驱动支持的视频格式 |
| `VIDIOC_TRY_FMT` | 验证格式是否可行（不实际生效） |
| `VIDIOC_S_FMT` / `VIDIOC_G_FMT` | 设置 / 读取视频捕获格式 |
| `VIDIOC_CROPCAP` | 查询驱动的裁剪能力 |
| `VIDIOC_S_CROP` / `VIDIOC_G_CROP` | 设置 / 获取视频信号边框 |
| `VIDIOC_REQBUFS` | 分配帧缓冲队列 |
| `VIDIOC_QUERYBUF` | 查询已分配缓冲区的长度和偏移量 |
| `VIDIOC_QBUF` | 把帧缓冲放入队列 |
| `VIDIOC_DQBUF` | 从队列中取出已填好数据的帧缓冲 |
| `VIDIOC_STREAMON` / `VIDIOC_STREAMOFF` | 开始 / 结束视频流采集 |

这些调用中，查询能力、设置格式、申请缓冲、映射、启停流是必需的，其余按需选用。例如查询能力：

```c
struct v4l2_capability cap;
ioctl(fd, VIDIOC_QUERYCAP, &cap);
```

## 完整采集流程

整个流程可以分成五个阶段：**打开查询 → 参数设置 → 缓冲区申请与映射 → 流式采集循环 → 收尾释放**。

### 1. 打开设备并查询能力

```c
int fd = open("/dev/video0", O_RDWR);

struct v4l2_capability cap;
ioctl(fd, VIDIOC_QUERYCAP, &cap);   /* 确认是否支持视频采集等能力 */
```

### 2. 设置采集参数

```c
ioctl(fd, VIDIOC_S_STD, &std_id);   /* 制式：PAL / NTSC */
ioctl(fd, VIDIOC_S_CROP, &crop);    /* 采集窗口大小 */
ioctl(fd, VIDIOC_S_FMT, &fmt);      /* 帧格式：像素格式、宽高 */
ioctl(fd, VIDIOC_S_PARM, &parm);    /* 帧率 */
ioctl(fd, VIDIOC_S_CTRL, &ctrl);    /* 旋转等控制项 */
```

### 3. 申请缓冲区并映射到用户空间

```c
/* 申请若干帧缓冲区，一般不少于 3 个 */
ioctl(fd, VIDIOC_REQBUFS, &req);

/* 查询每个缓冲区在内核空间中的长度和偏移量 */
ioctl(fd, VIDIOC_QUERYBUF, &buf);

/* 内存映射：拿到地址后可直接操作采集到的帧，无需拷贝 */
buffers[i].start = mmap(NULL, buffers[i].length,
                        PROT_READ | PROT_WRITE, MAP_SHARED,
                        fd, buffers[i].offset);
```

### 4. 流式采集循环

```c
/* 把所有帧缓冲排入采集队列，用于存放采集数据 */
ioctl(fd, VIDIOC_QBUF, &buf);

/* 开始视频流采集 */
ioctl(fd, VIDIOC_STREAMON, &type);
```

之后进入循环：

1. 驱动把采集到的一帧数据写入队列中的帧缓冲区，写完将其移入输出队列
2. 应用程序用 `VIDIOC_DQBUF` 取出已含数据的帧缓冲区，处理其中的原始视频数据
3. 处理完后用 `VIDIOC_QBUF` 把该缓冲区重新排回队列，供驱动继续填充

如此循环，直到停止采集：

```c
ioctl(fd, VIDIOC_STREAMOFF, &type);  /* 停止采集 */
```

### 5. 收尾释放

```c
munmap(buffers[i].start, buffers[i].length);  /* 解除映射 */
close(fd);                                    /* 关闭设备文件 */
```

实际运用中往往还要对采集到的视频数据做处理（如压缩编码），否则视频流数据量相当大，需要很大的存储空间和传输带宽。

## 采集参数结构体示例

一个管理 v4l2 采集的结构体示例：

```c
typedef struct tagT_V4l2CaptureAttr {
    char szDevName[MAX_NAME_LEN];
    int iWidth;
    int iHeight;
    int iFps;
    enum v4l2_buf_type eBufType;      /* 视频采集的 buff 类型，目前只支持 MPlanes */
    unsigned int uiPixelFormat;       /* 像素格式，例：V4L2_PIX_FMT_NV12 */
    enum v4l2_field eField;           /* 图像刷新模式 */
    enum v4l2_memory eMemoryType;     /* 读取帧使用的内存类型 */

    /* dma */
    int frmFdList[MAX_DMA_FD_LIST];
    void* frmPtrList[FRAME_REQUEST_CNT];
    int frmCnt;
} T_V4l2CaptureAttr;
```

## UVC 标准杂项

标准 UVC 设备需要支持 MJPG 和 YUYV 两种格式。由于 USB 2.0 的最高速率是 480 Mbps，传不动 1080p30 的裸数据，因此 YUYV 最大只支持 1280×960，只有 MJPG 压缩格式才能支持 1080p。

一个 USB 摄像机通常会生成多个 video 设备节点：一般有一个节点提供完整视频流，另一个节点功能受限（如仅用于拍照）。具体编号因设备而异，用下面的 v4l2-ctl 命令逐个确认即可。

## v4l2-ctl 实用命令

```bash
# 设备发现
v4l2-ctl --list-devices                          # 列出所有视频设备

# 设备信息
v4l2-ctl -d /dev/video0 --all                    # 获取指定设备的所有信息
v4l2-ctl -d /dev/video0 --list-formats-ext       # 列出设备支持的格式及分辨率范围
v4l2-ctl -d /dev/video0 --list-ctrls             # 列出设备控制项及当前值

# DV 时序（HDMI 采集卡等常用）
v4l2-ctl -d /dev/video11 --get-dv-timings        # 获取当前 DV 时序
v4l2-ctl -d /dev/video11 --get-dv-timings-cap    # 获取支持的 DV 时序范围
v4l2-ctl -d /dev/video11 --query-dv-timings      # 探测实际接入的 DV 时序
v4l2-ctl -d /dev/video11 --set-edid file=./1080.bin,format=raw  # 写入 EDID

# 抓流：指定分辨率和格式，采集 100 帧写入文件
v4l2-ctl -d /dev/video0 \
    --set-fmt-video=width=1920,height=1080,pixelformat=MJPG \
    --stream-mmap --stream-to=./output.mjpg --stream-count=100

# 设备支持 H264 编码时可直接存为 h264 裸流
v4l2-ctl -d /dev/video0 \
    --set-fmt-video=width=1920,height=1080,pixelformat=H264 \
    --stream-mmap --stream-to=./output --stream-count=100
```
